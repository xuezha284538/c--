# C++ 智能指针

## 前言

传统裸指针痛点：

1. `new` 之后忘记 `delete` → **内存泄漏**

2. 同一内存多次 `delete` → 程序崩溃

3. 异常场景下，delete 无法执行，内存泄漏

4. 多个指针共享同一块堆内存，生命周期难以管理

**智能指针核心思想：RAII（资源获取即初始化）**
将堆内存交给类对象管理；智能指针生命周期结束（析构）时，自动释放内存。
头文件：`#include <memory>`

C\+\+11 提供三种核心智能指针：

1. `std::unique_ptr` 独占所有权（推荐优先使用）

2. `std::shared_ptr` 共享所有权，引用计数

3. `std::weak_ptr` 配合 shared\_ptr，解决循环引用

---

# 一、std::unique\_ptr 独占智能指针

## 1\. 核心特性

- **独占语义**：一块堆内存只能被一个 unique\_ptr 持有

- **禁止拷贝构造、禁止赋值**；只支持移动语义 `std::move`

- 开销极小，几乎等同于裸指针，工程首选

- 生命周期结束自动释放内存

## 2\. 基础用法示例

```cpp
#include <iostream>
#include <memory>
using namespace std;

struct Person
{
    string name;
    Person(string n):name(n) { cout << "构造:" << name << endl; }
    ~Person() { cout << "析构:" << name << endl; }
};

int main()
{
    // 方式1：new初始化（不推荐）
    unique_ptr<Person> p1(new Person("张三"));

    // 方式2：推荐 make_unique (C++14)
    auto p2 = make_unique<Person>("李四");

    // 访问成员 -> / *解引用
    cout << p2->name << endl;
    cout << (*p2).name << endl;

    // 禁止拷贝！编译报错
    // unique_ptr<Person> p3 = p2;

    // 移动所有权，p2变为空
    unique_ptr<Person> p3 = move(p2);

    if(!p2)
        cout << "p2 已经是空指针" << endl;

    // 手动释放内存
    p3.reset();

    return 0;
}
```

## 3\. 常用成员函数

- `reset()`：释放原有资源，可传入新地址接管新内存

- `release()`：**放弃管理权**，返回裸指针，内存不会释放（慎用）

- `get()`：获取裸指针（仅临时访问，不要手动 delete）

- `swap()`：交换两个 unique\_ptr 管理的资源

## 4\. unique\_ptr 管理数组

```cpp
// 动态数组
auto arr = make_unique<int[]>(5);
arr[0] = 10;
```

> 优势：离开作用域自动释放数组，不需要`delete[]`

# 二、std::shared\_ptr 共享智能指针

## 1\. 核心特性

- **共享所有权**：多个 shared\_ptr 可以指向同一块堆内存

- 内部维护**引用计数器**

- 规则：每新增一个 shared\_ptr，计数 \+ 1；每销毁一个 shared\_ptr，计数 \- 1；**计数归 0 时释放堆内存**

## 2\. 基础示例

```cpp
#include <iostream>
#include <memory>
using namespace std;

struct Dog
{
    Dog() { cout << "Dog构造" << endl; }
    ~Dog() { cout << "Dog析构" << endl; }
};

int main()
{
    // 推荐 make_shared（内存分配更高效）
    shared_ptr<Dog> sp1 = make_shared<Dog>();
    cout << "引用计数:" << sp1.use_count() << endl; // 1

    // 允许拷贝，计数+1
    shared_ptr<Dog> sp2 = sp1;
    cout << "引用计数:" << sp1.use_count() << endl; // 2

    sp1.reset(); // sp1放弃管理，计数-1
    cout << "引用计数:" << sp2.use_count() << endl; //1

    sp2.reset(); // 计数变为0，内存释放
    return 0;
}
```

## 3\. 常用成员

- `use_count()`：获取当前引用计数（调试使用，不要用于业务判断）

- `reset()`：放弃资源管理

- `get()`：得到裸指针

- `unique()`：判断是否当前唯一持有者（C\+\+20 弃用）

## 4\. 重要注意事项

❌ 坑 1：不要用裸指针给多个 shared\_ptr 初始化！

```cpp
//错误示范
int* raw = new int(100);
shared_ptr<int> s1(raw);
shared_ptr<int> s2(raw); 
// s1、s2认为各自独立管理内存；析构时两次delete，崩溃！
```



# 三、std::weak\_ptr 弱智能指针

## 1\. 出现原因：shared\_ptr 循环引用（内存泄漏经典场景）

### 循环引用泄漏案例

```cpp
struct Node
{
    int val;
    shared_ptr<Node> next;
    Node(int v):val(v){}
};

int main()
{
    auto n1 = make_shared<Node>(1);
    auto n2 = make_shared<Node>(2);
    n1->next = n2;
    n2->next = n1;
    // 离开作用域：两个对象引用计数都为1，不会释放 → 内存泄漏
    return 0;
}
```

## 2\.weak\_ptr 特性

- **不增加引用计数**，弱引用；不拥有资源所有权

- 只能配合`shared_ptr`使用

- 作用：打破循环引用

- 不能直接解引用访问对象，必须调用`lock()`提升为 shared\_ptr

## 3\.weak\_ptr 使用代码

```cpp
#include <iostream>
#include <memory>
using namespace std;

struct Node
{
    int val;
    weak_ptr<Node> next; // 使用弱指针
    Node(int v):val(v){}
};

int main()
{
    auto n1 = make_shared<Node>(1);
    auto n2 = make_shared<Node>(2);
    n1->next = n2;
    n2->next = n1;
    // 作用域结束，内存正常释放，解决循环引用
    return 0;
}
```

## 4\. 核心接口

- `lock()`：返回`shared_ptr<T>`，资源存活则有效；资源已释放返回空 shared\_ptr

- `expired()`：判断指向资源是否已经被释放（true = 资源已销毁）

```cpp
auto sp = wp.lock();
if(sp)
{
    // 安全访问对象
}
```

# 四、三种智能指针选型策略（重点考点）

1. **优先使用 unique\_ptr**
资源只需要一个管理者，开销最低，性能最好。

2. 需要**多个地方共享同一份资源** → shared\_ptr

3. 使用 shared\_ptr 并且存在相互指向，有循环引用风险 → 配合 weak\_ptr

> 原则：能 unique 就不用 shared；shared 能不用就不用；weak\_ptr 仅作为配套工具。
>

# 五、自定义删除器（拓展）

智能指针默认使用`delete`释放内存。
场景：管理文件句柄、socket、第三方资源，需要自定义释放逻辑。

```cpp
// shared_ptr自定义删除器
void FileDel(FILE* f)
{
    cout << "关闭文件" << endl;
    fclose(f);
}

int main()
{
    FILE* fp = fopen("test.txt","w");
    shared_ptr<FILE> filePtr(fp, FileDel);
    // 离开作用域自动调用FileDel关闭文件
    return 0;
}
```

unique\_ptr 删除器写法略有区别（模板参数）。

# 六、高频易错点汇总

1. 不要保存智能指针`get()`返回的裸指针，裸指针生命周期不受智能指针管控；

2. 禁止多个独立 shared\_ptr 接管同一个裸指针；

3. unique\_ptr 不能拷贝，只能移动 move；

4. shared\_ptr 循环引用造成内存泄漏，使用 weak\_ptr 打破；

5. weak\_ptr 不可直接访问对象，必须 lock \(\)；

6. make\_shared/make\_unique 优先于 new，减少内存碎片，更安全；

7. 不要返回局部 unique\_ptr 引用，可以直接返回对象（触发移动语义）；

8. 智能指针作为容器元素完全支持（vector\<unique\_ptr\>）。

# 七、面试简答总结

1. RAII 是什么？资源获取即初始化，利用对象生命周期管理资源。

2. unique 独占、shared 计数共享、weak 弱引用不计数，解决 shared 循环引用。

3. shared\_ptr 循环引用为什么泄漏？相互持有导致引用计数无法归零。

4. shared\_from\_this 作用：安全获取指向自身的 shared\_ptr，禁止裸 this 构造 shared\_ptr。
