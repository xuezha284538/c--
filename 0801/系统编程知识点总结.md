## 写在前面：先建立两个基本概念

在开始之前，先理解两个贯穿全文的基础概念，否则后面会处处卡壳。

### 概念 1：用户态 vs 内核态

- **用户态**：你的程序运行的地方，权限受限，不能直接碰硬件、不能直接读硬盘。
- **内核态**：操作系统内核运行的地方，权限最高，能控制一切硬件。

你的程序想读文件、想收网络数据、想创建进程？**都不是自己动手，而是「请内核帮忙」**——这个"请求帮忙"的动作叫**系统调用（system call）**。

> 生活类比：你在餐厅（用户态）吃饭，想加菜不能自己冲进厨房（内核态），得叫服务员（系统调用）帮你下单。

所以 `open`/`read`/`write`/`fork` 这些都是「请内核干活」的接口。

### 概念 2：什么是 POSIX

POSIX 是一套**操作系统接口标准**（IEEE 制定）。遵循它的系统（Linux、MacOS、鸿蒙）都提供相同名字的函数（如 `read`、`fork`、`pthread_create`）。这样写出的代码可移植。你看到的 `io.c` 注释里写的「posix std」就是这个意思。

## 一、文件 I/O

### 1.1 UNIX「一切皆文件」【笔记 0521】

UNIX 哲学：**一切皆文件**。硬盘上的文件是文件，键盘、屏幕、网卡、目录……都被抽象成「文件」。好处是：用同一套 `read`/`write` 就能操作所有东西。

`ls -l` 第一列字符代表文件类型：

| 标识 | 类型 | 举例 |
|------|------|------|
| `-`  | 普通文件 | .txt、.c、可执行程序 |
| `d`  | 目录 | 文件夹 |
| `l`  | 软链接 | 快捷方式 |
| `b`  | 块设备 | 硬盘 /dev/sda |
| `c`  | 字符设备 | 键盘 /dev/tty、终端 |
| `p`  | 管道 | 管道文件 |
| `s`  | 套接字 | 网络通信 |

**流（stream）**：数据是「一串字节」流过去的。`stdin` 是输入流（读），`stdout` 是输出流（写）。

---

### 1.2 标准库 I/O（C 库函数）【笔记 0521】

这是你在 C 语言课最早学的文件操作，封装在 `stdio.h` 里。

**特点**：操作 `FILE*` 文件流指针，**自带用户态缓冲区**，跨平台。

> 什么是缓冲区？你写一个字节就喊内核一次太浪费。标准库先攒一批数据在内存（缓冲区），攒够了再一次性交给内核。就像寄快递，一件一件寄太贵，攒一箱一起寄便宜。

| 函数 | 作用 | 粒度 |
|------|------|------|
| `fopen` / `fclose` | 打开 / 关闭文件 | — |
| `fgetc` / `fputc` | 读 / 写**一个字符** | 字符 |
| `fgets` / `fputs` | 读 / 写**一行字符串** | 行 |
| `fread` / `fwrite` | 读 / 写**一块二进制** | 块（图片、word、程序） |
| `fseek` | 移动读写位置（随机访问） | — |
| `ftell` | 获取当前距文件开头的字节数 | — |
| `rewind` | 回到文件开头 | — |
| `fprintf` | 格式化输出到文件 | — |

**打开模式**（`fopen` 第二参数）：`"r"` 只读、`"w"` 只写（清空）、`"a"` 追加、`"b"` 二进制（如 `"rb"`）。

### 1.3 系统调用级文件 I/O【补充 + io.c 实践】

这是笔记里讲得不够、但你在 `io.c` 里正在用的部分。**重点详解。**

#### 1.3.1 文件描述符（fd）—— 最核心概念

系统调用不认识 `FILE*`，它只认一个**小整数**，叫**文件描述符（file descriptor, fd）**。

每个进程启动时，内核默认给它打开 3 个：

| fd | 名字 | 指向 | 你能怎么用 |
|----|------|------|-----------|
| 0 | `STDIN_FILENO` | 标准输入（键盘） | `read(0, buf, n)` 从键盘读 |
| 1 | `STDOUT_FILENO` | 标准输出（屏幕） | `write(1, buf, n)` 往屏幕写 |
| 2 | `STDERR_FILENO` | 标准错误（屏幕） | `write(2, msg, n)` 输出错误 |

> 这就解释了你 `io.c` 里的 `read(0,buf,n)` 和 `write(1,buf,n)`：0 是键盘，1 是屏幕。

**分配规则**：当你 `open` 一个新文件，内核把**当前最小未使用的整数**分配给它。所以新打开的文件 fd 通常是 **3**（因为 0、1、2 被占了）。

```
进程打开文件表（内核维护）
下标(fd)  →  指向的文件
  0       →  键盘
  1       →  屏幕
  2       →  屏幕(错误)
  3       →  你 open 的 test.txt   ← 新分配
  4       →  你 open 的另一个文件
```

#### 1.3.2 open 函数 —— 打开/创建文件

```c
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>

int open(const char *pathname, int flags);                       // 不创建文件用这个
int open(const char *pathname, int flags, mode_t mode);          // 用了 O_CREAT 就用这个
// 返回：成功 fd(非负)；失败 -1
```

**参数详解**：

- `pathname`：文件路径，相对/绝对都行。
- `flags`：打开方式，**必须**包含下列之一（访问模式）：
  - `O_RDONLY` 只读
  - `O_WRONLY` 只写
  - `O_RDWR`   读写
  
  可以再 `|` 组合这些可选标志：
  - `O_CREAT`   文件不存在就创建（**这时必须给第三个参数 mode**）
  - `O_TRUNC`   文件存在就把内容清空
  - `O_APPEND`  每次写在文件末尾（追加）
  - `O_EXCL`    配合 O_CREAT，文件已存在则报错（用来"确保只我创建"）
  - `O_NONBLOCK`非阻塞模式

- `mode`：文件权限，**八进制**，如 `0644` = 拥有者读写、其他人只读。
  - 注意：实际权限 = `mode & ~umask`。`umask` 是进程的权限掩码（默认 022），会"砍掉"部分权限。

> 新手坑：用了 `O_CREAT` 却忘了写 `mode` → 编译可能过，但权限是乱七八糟的随机值。永远记住：**有 O_CREAT 就有 mode**。

#### 1.3.3 read / write / close / lseek

```c
#include <unistd.h>
ssize_t read(int fd, void *buf, size_t count);
ssize_t write(int fd, const void *buf, size_t count);
int close(int fd);
off_t lseek(int fd, off_t offset, int whence);
```

逐个说明：

**read**：从 fd 对应文件读 `count` 字节到 `buf`。
- 返回值类型是 `ssize_t`（**有符号**，能表示 -1）。**别用 int 接**——在大文件场景可能溢出。
- 返回值 = **实际读到的字节数**，可能 < count（比如文件就剩 10 字节你却要 100）。
- 返回 **0 = 读到文件末尾（EOF）**，这是循环读文件结束的标志。
- 返回 **-1 = 出错**，错误码在 `errno`。

**write**：把 `buf` 前 `count` 字节写入 fd。
- 返回**实际写入字节数**，可能 < count（磁盘满、特殊情况）。
- 严谨写法：循环写，直到全部写完。

**close**：关闭 fd，释放资源。**返回 0 成功，-1 失败**。
- 新手坑：打开了不关 → fd 泄漏，进程能打开的 fd 数有限（默认 1024），耗尽后 open 就失败。

**lseek**：移动文件的"读写指针"（光标）。
- `whence`：基准点。`SEEK_SET` 文件开头、`SEEK_CUR` 当前位置、`SEEK_END` 文件末尾。
- 返回值 = 新位置距开头的偏移量。
- 经典用法：`lseek(fd, 0, SEEK_END)` 返回值就是**文件大小**。

#### 1.3.4 errno 与 perror —— 错误怎么查

系统调用失败时返回 -1，并把**具体错误原因**写进全局变量 `errno`（`<errno.h>`）。但 `errno` 是个数字，看不懂，所以有：

```c
#include <stdio.h>
void perror(const char *s);   // 打印 "s: 错误描述"
#include <string.h>
char *strerror(int errnum);   // 返回错误描述字符串
```

用法：`perror("open failed");` → 输出 `open failed: No such file or directory`。

#### 1.3.5 完整可运行示例

```c
/* file_io.c —— 系统调用文件读写完整示例 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>

int main() {
    // 1. 打开/创建文件：只写，不存在则创建，存在则清空，权限 0644
    int fd = open("hello.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd == -1) { perror("open failed"); return -1; }
    printf("打开成功，fd = %d\n", fd);   // 通常打印 3

    // 2. 写入数据
    const char *msg = "Hello, Linux File IO!\n";
    ssize_t n = write(fd, msg, strlen(msg));
    if (n == -1) { perror("write failed"); close(fd); return -1; }
    printf("写入了 %zd 字节\n", n);

    // 3. 关闭文件（一定要关！）
    close(fd);

    // 4. 重新以只读打开，读回内容
    fd = open("hello.txt", O_RDONLY);
    if (fd == -1) { perror("open read failed"); return -1; }

    char buf[128] = {0};                 // 注意初始化为 0，否则可能有脏数据
    ssize_t r = read(fd, buf, sizeof(buf) - 1);  // 留 1 字节给 '\0'
    if (r > 0) {
        buf[r] = '\0';                   // 手动补结束符，才能用 %s 打印
        printf("读到 %zd 字节: %s\n", r, buf);
    }
    close(fd);
    return 0;
}
```

编译运行：
```bash
gcc file_io.c -o file_io
./file_io
```

> **回答你 `io.c` 里的疑问**：
> - `char buf[16]={0};` —— 初始化为 0，避免缓冲区有脏数据被 `write` 一起写出去。
> - `read(0, buf, sizeof(buf)-1)` —— 用 `-1` 是给字符串结束符 `\0` 留位置，否则之后用 `%s` 打印会越界。
> - `write(1, buf, n)` —— `n` 是 `read` 的返回值（实际读了多少），只写实际读到的字节，不写整个 16。

#### 1.3.6 标准 IO vs 系统调用 IO 对比

| 特性 | 系统调用 IO | C 库标准 IO |
|------|------------|-------------|
| 操作对象 | 文件描述符（int） | 文件流指针（FILE*） |
| 缓存 | 无用户态缓存，每次都进内核 | 有用户态缓存，攒一批再进内核 |
| 函数 | open/read/write/close | fopen/fread/fwrite/fclose |
| 移植性 | 依赖内核，弱（Linux 专属多） | 跨平台，强 |
| 速度 | 频繁调用慢 | 缓存命中快 |
| 适用 | 设备文件、套接字、管道、需要实时 | 普通文本/二进制文件 |

**一句话**：`fopen` 内部其实就是调了 `open`，然后加了个缓存层。底层是系统调用，上层是标准库。

#### 1.3.7 重定向原理【补充】

你用过 `./a.out > out.txt` 吧？原理就是改 fd 指向：

```c
close(1);                                        // 关闭标准输出
int fd = open("out.txt", O_WRONLY|O_CREAT, 0644); // 新文件抢占 fd=1
printf("这行不会显示在屏幕，而是写进 out.txt\n");   // printf 向 fd=1 写
fflush(stdout);                                  // 别忘了刷缓冲区
```

更优雅的方式：`dup2(oldfd, newfd)` —— 把 newfd 关掉，让它指向 oldfd 同一个文件。

### 1.4 目录操作【笔记 0525/0531】

```c
#include <dirent.h>
DIR *opendir(const char *name);              // 打开目录，返回目录流
struct dirent *readdir(DIR *dirp);           // 逐项读取目录条目
int closedir(DIR *dirp);                     // 关闭目录
```

`struct dirent` 常用字段：`d_name`（文件名）。

```c
/* 列出当前目录所有文件 */
DIR *d = opendir(".");
struct dirent *ent;
while ((ent = readdir(d)) != NULL) {
    printf("%s\n", ent->d_name);
}
closedir(d);
```

应用：`wc` 统计目录代码行数、文件切分（bit torrent 协议）。

## 二、进程控制【补充 + 笔记 0612】

### 2.1 进程 vs 线程【笔记 0612】

- **进程**：程序的一次执行过程，及获得的 CPU、内存、文件、网络等资源。一个程序默认一个进程，**进程间资源相互隔离**。
- **线程**：进程里的执行单元，一个进程默认一个主线程，**多线程共享进程资源**。

> 类比：进程 = 一套房子（独立厨房、卫生间）；线程 = 房子里住的人（共享厨房、卫生间）。

每个进程有唯一 PID，可用 `getpid()` 获取；父进程 PID 用 `getppid()`。

### 2.2 fork() —— 创建子进程

#### 2.2.1 它做了什么

`fork` 把当前进程"复制"一份，产生子进程。子进程是父进程的**几乎完整副本**（代码段、数据段、堆、栈、文件描述符表都拷一份）。

```c
#include <unistd.h>
pid_t fork(void);
```

#### 2.2.2 最反直觉的点：一次调用，两次返回

这是新手最容易懵的地方。`fork()` 执行后：
- **父进程**里返回 **子进程的 PID（>0）**
- **子进程**里返回 **0**
- 失败返回 **-1**

为什么？因为 fork 之后**变成两个进程**，各自从 fork 返回处继续往下跑，各自拿到自己的返回值。

```c
pid_t pid = fork();
if (pid < 0) {
    perror("fork failed");
} else if (pid == 0) {
    // 这里是子进程（返回值为 0）
    printf("我是子进程, PID=%d, 父PID=%d\n", getpid(), getppid());
} else {
    // 这里是父进程（返回值是子进程 PID）
    printf("我是父进程, PID=%d, 我的子进程=%d\n", getpid(), pid);
}
```

> 类比：你（父）克隆了一个自己（子）。克隆完成那一刻，两个人各自醒来，都问"我是谁？"——克隆机告诉你"你是副本"（返回 0），告诉原版"那是你的副本编号 1234"（返回 1234）。

#### 2.2.3 写时复制（Copy-On-Write, COW）

新手会担心：fork 把整个内存复制一份，太费内存了吧？现代 Linux 用 **COW** 优化：fork 时**先不真的复制**，父子共享同一份物理内存（页表标记只读）。**只有当某一方要写数据时**，内核才真正为那一页复制一份。

> 类比：两个人共用一本笔记本，谁都没写就共用；谁要写了，复印那一页给他自己改。

#### 2.2.4 fork 后谁先执行？—— 不确定

由调度器决定，**不能假设**父先或子先。需要顺序就靠同步机制（信号、管道、信号量）。

#### 2.2.5 文件描述符继承

fork 后子进程**继承父进程的文件描述符表**，且指向**同一个打开文件**（共享文件偏移量）。所以父子都能操作同一文件——这是管道通信的基础。

#### 2.2.6 常见用法
- 网络服务器：父进程 `accept` 来一个连接，`fork` 子进程处理，父继续监听。
- 配合 `exec`：fork 后子进程立刻 exec 换成新程序（shell 执行命令就是这个套路）。

### 2.3 exec 系列 —— 替换进程映像

`fork` 只是复制自己，但子进程跑的还是同一份代码。想让子进程**跑别的程序**（比如 `ls`），就用 `exec`。

`exec` 把当前进程的**代码和数据整个换掉**，加载新程序。**不创建新进程，PID 不变**——就像一个人换了灵魂，躯壳（PID）还是那个。

```c
#include <unistd.h>
int execl(const char *path, const char *arg, ... /* (char*)NULL */);
int execlp(const char *file, const char *arg, ...);
int execv(const char *path, char *const argv[]);
int execvp(const char *file, char *const argv[]);
int execve(const char *path, char *const argv[], char *const envp[]);  // 真正的系统调用
```

**函数名后缀含义**（背下来就全会了）：
- `l`（list）：参数一个一个列出来传
- `v`（vector）：参数打包成数组传
- `p`（path）：去 `PATH` 环境变量里找程序（所以只写文件名即可）
- `e`（env）：传自定义环境变量

**关键点**：`exec` 成功后**不会返回**（原代码已被覆盖）。**只有失败才返回 -1**。所以 exec 后面直接写错误处理即可：

```c
pid_t pid = fork();
if (pid == 0) {
    // 子进程：换成 ls 程序
    execlp("ls", "ls", "-l", "-a", NULL);
    // 只有 exec 失败才会走到这里
    perror("exec failed");
    exit(1);
}
// 父进程继续...
```

> 新手坑：参数列表**必须以 `NULL` 结尾**，否则 exec 不知道参数到哪结束，会读到乱内存。

### 2.4 进程终止 exit / _exit

```c
#include <stdlib.h>
void exit(int status);       // 库函数：先刷缓冲区、调清理函数，再调 _exit
#include <unistd.h>
void _exit(int status);      // 系统调用：直接退出，啥也不收拾
```

- `exit` 会**刷新 stdio 缓冲区**（你 `printf` 没加 `\n` 的内容会被刷出来）。
- `_exit` 不刷新，直接进内核销毁进程。
- `main` 里 `return 0;` 等价于 `exit(0)`。

**退出码 `status`**：低 8 位传给父进程的 `wait`，表示进程"怎么死的"。

退出场景：
- 正常：`return`、`exit()`、`_exit()`
- 异常：被信号杀死（`SIGSEGV` 段错误、`Ctrl+C` 发 `SIGINT`）——退出码里会带信号信息。

---

### 2.5 僵尸进程与孤儿进程【重点】

#### 2.5.1 僵尸进程（Zombie）

子进程退出后，**内核还会保留它的 PID、退出状态、资源统计**等信息，等父进程来"收尸"（用 `wait` 读取）。在父进程收尸前，子进程就处于**僵尸态（Z 状态）**。

> 类比：人死了但尸体还在太平间，等家属（父进程）来认领。家属不来，尸体就一直占着位置。

**危害**：僵尸进程虽不占内存，但占 PID。PID 耗尽后系统就起不了新进程了。

#### 2.5.2 孤儿进程

父进程先死了，子进程就成了孤儿，被 `init`（PID 1）收养。`init` 会自动收尸，所以孤儿进程**不危害**。

#### 2.5.3 wait / waitpid —— 收尸

```c
#include <sys/wait.h>
pid_t wait(int *status);                                   // 阻塞等任意子进程
pid_t waitpid(pid_t pid, int *status, int options);        // 灵活：指定 pid、可非阻塞
```

- `wait`：阻塞，直到任意一个子进程结束，返回该子进程 PID。
- `waitpid`：
  - `pid > 0`：等指定子进程；`pid == -1`：等任意子进程（同 wait）。
  - `options`：`WNOHANG` 表示**不阻塞**（没有子进程结束就立刻返回 0）。

**解析状态码的宏**（`status` 不能直接看，要用宏）：
- `WIFEXITED(status)`：是否正常退出
- `WEXITSTATUS(status)`：退出码（仅当 WIFEXITED 为真）
- `WIFSIGNALED(status)`：是否被信号杀死
- `WTERMSIG(status)`：哪个信号杀的

```c
int status;
pid_t w = wait(&status);
if (WIFEXITED(status))
    printf("子进程 %d 正常退出, 退出码 %d\n", w, WEXITSTATUS(status));
else if (WIFSIGNALED(status))
    printf("子进程 %d 被信号 %d 杀死\n", w, WTERMSIG(status));
```

#### 2.5.4 完整 fork+wait 示例

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>
#include <stdlib.h>

int main() {
    pid_t pid = fork();
    if (pid < 0) { perror("fork"); exit(1); }
    if (pid == 0) {
        // 子进程：干活，干完退出
        printf("子进程 PID=%d, 干活 2 秒...\n", getpid());
        sleep(2);
        exit(42);   // 退出码 42
    }
    // 父进程：等子进程
    printf("父进程 PID=%d, 等待子进程 %d...\n", getpid(), pid);
    int status;
    waitpid(pid, &status, 0);
    if (WIFEXITED(status))
        printf("子进程结束, 退出码=%d\n", WEXITSTATUS(status));
    return 0;
}
```

#### 2.5.5 防僵尸的常用套路
父进程太忙不想一直 `wait`？**捕获 `SIGCHLD` 信号**：子进程退出时内核会给父进程发 `SIGCHLD`，在信号处理函数里调 `waitpid` 收尸即可。

---

### 2.6 vfork / clone【补充】
- `vfork`：父子**共享**地址空间（不复制），子进程先跑，子进程结束/`exec` 前父进程阻塞。**不推荐**，容易踩坑。
- `clone`：底层系统调用，通过 flags 精确控制父子共享哪些资源（`CLONE_VM` 共享内存、`CLONE_FILES` 共享 fd）。**Linux 的线程本质就是 clone 出来的进程**（共享内存但独立栈）。

## 三、进程间通信（IPC）

### 3.0 为什么需要 IPC

进程地址空间**相互隔离**，进程 A 不能直接读进程 B 的内存。要协作就得靠**内核当中间人**——A 把数据交给内核，B 从内核取。

速度排序：**共享内存 > 管道 > 消息队列 > Socket**
灵活性：**Socket > 消息队列 > 管道**

---

### 3.1 匿名管道 pipe【补充】

#### 3.1.1 原理
内核里的一块**环形缓冲区**（默认 64KB），配两个 fd：`fd[0]` 读、`fd[1]` 写。

> 类比：一根水管，一头灌水一头接水。水只能单向流。

#### 3.1.2 特点
- **半双工**（单向）：要双向得建两根管。
- **只能用于有亲缘关系的进程**（父子）。为啥？因为 fd 要靠 `fork` 继承传递。
- **面向字节流**：没有"消息边界"，发 3 次 "abc" 收到可能是 "abcabcabc"。
- 生命周期随进程。

#### 3.1.3 阻塞语义（重要！）
- 管道**空**时 `read` → **阻塞**，等有数据。
- 管道**满**时 `write` → **阻塞**，等读端取走。
- **所有写端关闭**，`read` 返回 **0**（EOF）——这是判断"对方写完了"的标志。
- **所有读端关闭**，`write` 触发 **SIGPIPE** 信号（默认终止进程）。

#### 3.1.4 标准用法
父 `pipe` 建管 → `fork` → 父子各关一端（一个只读一个只写）→ 通信。

```c
#include <unistd.h>
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

int main() {
    int fd[2];
    pipe(fd);                          // fd[0]读, fd[1]写

    if (fork() == 0) {                 // 子进程：读
        close(fd[1]);                  // 关掉写端（我不写）
        char buf[64] = {0};
        read(fd[0], buf, sizeof(buf)); // 没数据会阻塞
        printf("子进程收到: %s\n", buf);
        close(fd[0]);
    } else {                          // 父进程：写
        close(fd[0]);                  // 关掉读端（我不读）
        write(fd[1], "Hello IPC!", 11);
        close(fd[1]);                  // 写完关掉，子进程才能读到 EOF
    }
    return 0;
}
```

> 新手坑：不关不用的那一端 → 管道永远不"空"也不"满"，read 永远阻塞。**原则：不用就关**。

---

### 3.2 命名管道 FIFO【补充】

匿名管道只能给亲缘进程用。FIFO 在**文件系统里有个名字**，任意进程都能 `open` 它来通信。

```c
#include <sys/stat.h>
int mkfifo(const char *pathname, mode_t mode);   // 创建 FIFO 文件
```

之后用 `open`/`read`/`write` 像操作普通文件一样。

```bash
mkfifo /tmp/myfifo         # 命令行也能建
echo "hi" > /tmp/myfifo &  # 一个终端写
cat /tmp/myfifo            # 另一个终端读
```

| 特性 | 匿名管道 | 命名管道 |
|------|---------|---------|
| 标识 | 无名，仅 fd | 有路径，文件系统可见 |
| 范围 | 亲缘进程 | 任意进程 |
| 生命周期 | 随进程退出释放 | 需手动 unlink 删除 |

---

### 3.3 消息队列【补充】

内核维护的**消息链表**。每条消息带"类型 + 数据"，可按类型过滤读。比管道多了**消息边界**和**类型筛选**。

```c
// System V
int msgget(key_t key, int msgflg);                                       // 创建/获取队列
int msgsnd(int msqid, const void *msgp, size_t msgsz, int msgflg);      // 发
ssize_t msgrcv(int msqid, void *msgp, size_t msgsz, long msgtyp, int msgflg);  // 收
```

消息结构必须自定义，且**第一个字段必须是 `long` 类型**（放消息类型）：

```c
struct my_msg {
    long mtype;        // 必须是 long，消息类型
    char mtext[100];   // 数据
};
```

缺点：数据要两次拷贝（用户→内核→用户），不如共享内存快。

---

### 3.4 共享内存【补充】

让两个进程**映射同一块物理内存**，直接读写，**最快的 IPC**（零拷贝）。

> 类比：两人在同一块白板上写字，不用经过第三方。

```c
// System V
int shmget(key_t key, size_t size, int shmflg);     // 创建/获取
void *shmat(int shmid, const void *addr, int shmflg); // 映射到本进程地址空间
int shmdt(const void *addr);                         // 解除映射
int shmctl(int shmid, IPC_RMID, NULL);              // 删除
```

**致命点**：共享内存**没有任何同步机制**！两个进程同时写会冲突。所以**必须配合信号量/互斥锁**用。

---

### 3.5 信号量【补充 + 笔记 0617】

**注意：信号 ≠ 信号量！** 信号是异步通知，信号量是原子计数器。

信号量本质是个**原子计数器**，用来控制"同时能有多少人访问资源"。

- **二元信号量**（0/1）：当互斥锁用。
- **计数信号量**（如 3）：允许 3 个进程同时进入。

**P/V 操作**：
- **P（wait）**：申请资源。若 sem>0 则 sem-- 拿到；若 sem==0 则阻塞等。
- **V（post）**：释放资源，sem++，唤醒等待者。

POSIX 版（常用）：
```c
#include <semaphore.h>
sem_t sem;
sem_init(&sem, 0, 1);     // 参数2: 0=线程间, 1=进程间; 参数3: 初始值
sem_wait(&sem);           // P
// ... 临界区 ...
sem_post(&sem);           // V
sem_destroy(&sem);
```

System V 版：`semget`/`semop`，接口繁琐，老代码才用。

---

### 3.6 Socket【笔记网络编程部分】
最强大，支持**跨主机**通信，见第八章。

## 四、信号机制【补充】

### 4.0 信号是什么

信号是内核发给进程的**异步通知**（"软件中断"）。它只传一个**编号**，不传数据（少量信号可带少量数据）。

> 类比：你正在打游戏（主程序运行），突然电话响了（信号来了）。你暂停游戏去接电话（进入信号处理函数），接完回来继续打。

**特点**：
- **异步**：你不知道信号什么时候来。
- 只适合"事件通知"，不适合传大量数据。

### 4.1 信号的一生
1. **产生**：键盘 `Ctrl+C`、`kill` 命令、`alarm` 定时、程序异常。
2. **注册（未决 pending）**：内核在进程 PCB 里标记"有信号待处理"。
3. **递达**：进程从内核态返回用户态时检查并交给进程。
4. **处理**：执行对应动作。

**关键区分**：
- **阻塞**：信号来了但暂不递达（先攒着），解除阻塞后再处理。
- **忽略**：信号递达了，但直接丢掉不处理。
- 两者不一样！阻塞是"先不看"，忽略是"看了但不管"。

### 4.2 常用信号（背这几个就够）

| 信号 | 编号 | 默认动作 | 能捕获? | 场景 |
|------|------|---------|--------|------|
| SIGINT | 2 | 终止 | ✅ | `Ctrl+C` |
| SIGQUIT | 3 | 终止+core | ✅ | `Ctrl+\` |
| SIGKILL | 9 | 强制终止 | ❌ | `kill -9`，不可捕获/忽略/阻塞 |
| SIGSEGV | 11 | 终止+core | ✅ | 段错误（访问非法内存） |
| SIGPIPE | 13 | 终止 | ✅ | 向已关闭读端的管道写 |
| SIGALRM | 14 | 终止 | ✅ | `alarm` 定时到期 |
| SIGTERM | 15 | 终止 | ✅ | `kill` 默认信号，优雅退出 |
| SIGCHLD | 17 | 忽略 | ✅ | 子进程退出通知父进程 |
| SIGSTOP | 19 | 暂停 | ❌ | 不可捕获 |

> `SIGKILL`(9) 和 `SIGSTOP`(19) 是"上帝信号"——谁也拦不住，系统保留的最终手段。
> `SIGTERM` 是礼貌的"请退出"，`SIGKILL` 是直接"拔电源"。

### 4.3 三种处理方式
1. **默认（`SIG_DFL`）**：用系统默认动作。
2. **忽略（`SIG_IGN`）**：假装没收到。
3. **自定义函数（捕获）**：执行你写的函数。

### 4.4 核心 API

```c
#include <signal.h>

// 老接口，简单但不可靠（不同系统行为不一）
typedef void (*sighandler_t)(int);
sighandler_t signal(int signum, sighandler_t handler);

// 推荐接口，功能强大
int sigaction(int signum, const struct sigaction *act, struct sigaction *oldact);

int kill(pid_t pid, int sig);              // 给指定进程发信号
int raise(int sig);                        // 给自己发信号
unsigned int alarm(unsigned int seconds); // N 秒后给自己发 SIGALRM
int pause(void);                            // 阻塞直到收到任意信号
```

### 4.5 完整示例：捕获 Ctrl+C 优雅退出

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

volatile int running = 1;   // volatile! 防止编译器优化掉对它的检查

void handler(int sig) {
    // 信号处理函数里别用 printf（不安全）！这里演示用
    const char *msg = "收到 SIGINT，准备退出...\n";
    write(1, msg, 20);      // write 是异步信号安全的，可以用
    running = 0;
}

int main() {
    struct sigaction sa;
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);   // 不额外阻塞别的信号
    sa.sa_flags = 0;
    sigaction(SIGINT, &sa, NULL);   // 捕获 Ctrl+C

    while (running) {
        printf("运行中... 按 Ctrl+C 退出\n");
        sleep(1);
    }
    printf("已优雅退出\n");
    return 0;
}
```

### 4.6 信号处理函数的坑【重点】
信号处理函数里**不能随便调用函数**！因为信号随时打断主程序，如果主程序正在 `malloc`（持锁中），信号里又调 `malloc` → 死锁。

**只能用"异步信号安全"（Async-Signal-Safe）函数**：`write`、`read`、`_exit`、`waitpid` 等。**禁用 `printf`、`malloc`、`fopen`** 等。

实在要打印就用 `write(1, ...)` 或先 `sprintf` 到 buf 再 `write`。

## 五、多线程编程【笔记 0612】

### 5.1 为什么要多线程
- 进程切换开销大（要换地址空间）；线程切换开销小（共享地址空间）。
- 线程间通信方便（直接共享变量），但要处理同步。

### 5.2 POSIX 线程
POSIX 标准的线程接口叫 `pthread`。编译要加 `-lpthread`（或 `-pthread`）。

```bash
gcc thread.c -o thread -lpthread
```

### 5.3 线程生命周期【笔记 0612】
新建（`pthread_create`）→ 就绪（OS 调度）→ 运行 → 阻塞（`sleep`/`wait` 主动让 CPU）→ 结束。

### 5.4 核心 API

```c
#include <pthread.h>
int pthread_create(pthread_t *thread, const pthread_attr_t *attr,
                   void *(*start_routine)(void *), void *arg);
int pthread_join(pthread_t thread, void **retval);   // 等子线程结束，取返回值
int pthread_exit(void *retval);                       // 结束自己
int pthread_cancel(pthread_t thread);                 // 取消别的线程
```

### 5.5 完整示例

```c
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

void *worker(void *arg) {
    int id = *(int *)arg;
    for (int i = 0; i < 3; i++) {
        printf("子线程 %d: 第 %d 次\n", id, i);
        sleep(1);
    }
    int *result = malloc(sizeof(int));
    *result = id * 100;
    return result;            // 返回值，pthread_join 能拿到
}

int main() {
    pthread_t t1, t2;
    int a = 1, b = 2;
    pthread_create(&t1, NULL, worker, &a);
    pthread_create(&t2, NULL, worker, &b);

    void *r1, *r2;
    pthread_join(t1, &r1);    // 等 t1 结束
    pthread_join(t2, &r2);    // 等 t2 结束
    printf("t1 返回 %d, t2 返回 %d\n", *(int*)r1, *(int*)r2);
    free(r1); free(r2);
    return 0;
}
```

### 5.6 分离态 vs 非分离态【笔记 0612】

| | 分离态（detached） | 非分离态（默认 joinable） |
|--|--|--|
| 资源回收 | 结束自动释放 | 必须 `pthread_join` 回收 |
| 返回值 | 拿不到 | 能拿到 |
| 不处理后果 | — | 变**僵死线程**（占资源） |

设置分离：`pthread_detach(pthread_self());` 或创建时用属性设。

> 关键：`main` 里 `return` 结束的是**整个进程**，所有子线程一起销毁。要等子线程就用 `pthread_join`，或用 `pthread_exit(NULL)` 只结束主线程、进程不退。

## 六、线程同步【笔记 0617 / 0707】

### 6.0 为什么需要同步
多线程共享变量，如果同时读写会**数据竞争**。例：两个线程都 `count++`，`count++` 实际是"读-改-写"三步，可能交叉，导致少加一次。所以需要**锁**保证一次只有一个线程操作。

### 6.1 同步方法总览

| 方法 | 一句话 | 适用 |
|------|--------|------|
| 互斥锁 mutex | 排他锁，抢不到就睡 | 通用，临界区较大 |
| 条件变量 cond | 等待某条件成立 | 生产者-消费者 |
| 信号量 sem | 原子计数器 | 控制资源数量 |
| 读写锁 rwlock | 读共享、写独占 | 读多写少 |
| 自旋锁 spinlock | 抢不到就死循环等 | 多核、临界区极小 |

### 6.2 互斥锁 mutex

```c
pthread_mutex_t lock;
pthread_mutex_init(&lock, NULL);   // 或 PTHREAD_MUTEX_INITIALIZER 静态初始化
pthread_mutex_lock(&lock);         // 加锁，抢不到阻塞
// ... 临界区：只有一个线程能进 ...
pthread_mutex_unlock(&lock);       // 解锁
pthread_mutex_destroy(&lock);
```

**死锁条件**（4 个全满足才死锁）：互斥、占有等待、不可剥夺、循环等待。避免：**固定加锁顺序**、用 `pthread_mutex_timedlock` 带超时。

### 6.3 条件变量【笔记 0707】

用来"等待某事发生"。必须**配互斥锁**用。

```c
pthread_cond_t cond;
pthread_mutex_t lock;
pthread_cond_init(&cond, NULL);

// 等待方
pthread_mutex_lock(&lock);
while (条件不成立)                       // 必须用 while，防虚假唤醒！
    pthread_cond_wait(&cond, &lock);     // 自动解锁并睡，被唤醒后自动加锁
// 处理...
pthread_mutex_unlock(&lock);

// 通知方
pthread_mutex_lock(&lock);
// 改变条件...
pthread_cond_signal(&cond);             // 叫醒一个
// pthread_cond_broadcast(&cond);        // 叫醒所有
pthread_mutex_unlock(&lock);
```

> 新手坑：用 `if` 而不是 `while` 判断条件 → **虚假唤醒**会让程序出错。POSIX 明确规定 `cond_wait` 可能虚假返回，**必须 while 循环重判条件**。

### 6.4 信号量【笔记 0617】

见 3.5。`sem_wait`/`sem_post`，可替代互斥锁，也能控制资源数（如停车场车位）。

### 6.5 自旋锁 vs 互斥锁【笔记 0617】
- **自旋锁**：抢不到锁就**死循环（轮询）**，不睡觉。**单核没用**（浪费 CPU），为多核设计。适用**临界区极小**（几条指令）。
- **互斥锁**：抢不到就**睡**（阻塞），让出 CPU。单核多核都行，适用**临界区较大**。

> 类比：互斥锁 = 抢不到厕所就坐着玩手机等（不费劲但慢）；自旋锁 = 站门口不停敲门（费劲但反应快）。

### 6.6 经典问题
- **哲学家进餐**：5 人 5 筷，每人要 2 筷才能吃 → 容易死锁。解法：限制人数、奇偶编号拿筷顺序。
- **生产者-消费者**：用条件变量 + 互斥锁 + 缓冲区。

## 七、I/O 多路复用【补充】

### 7.0 解决什么问题
传统阻塞 IO：一个线程只能盯一个连接。1000 个连接就要 1000 个线程 → 内存爆（每线程默认 8MB 栈）、CPU 切换爆炸。

**多路复用**：一个线程同时盯**几千几万个 fd**，谁有数据就处理谁。

> 类比：一个服务员（线程）同时盯 1000 桌客人（fd），谁举手（就绪）就去哪桌。不用每桌配个服务员。

注意：select/poll/epoll 都是**同步 IO**——它们只告诉你"谁就绪了"，真正的 `read` 还是要你自己阻塞读。

### 7.1 select

```c
int select(int nfds, fd_set *readfds, fd_set *writefds,
           fd_set *exceptfds, struct timeval *timeout);
```

- `fd_set` 是个**位图**，每一位对应一个 fd。
- `FD_ZERO`/`FD_SET`/`FD_CLR`/`FD_ISSET` 操作位图。
- **最大监听 1024**（`FD_SETSIZE` 限制）。
- 每次调用：fd_set **全量拷贝**到内核 → 内核**遍历所有 fd** → 拷贝回来 → 用户再遍历找就绪的。
- `fd_set` 会被内核改，**每次都要重新设置**。

缺点：1024 上限、两次全量遍历、全量拷贝。**高并发不堪用**。

### 7.2 poll

```c
struct pollfd { int fd; short events; short revents; };
int poll(struct pollfd *fds, nfds_t nfds, int timeout);
```

- 用结构体数组代替位图，**取消 1024 限制**。
- 分离 `events`（想监听）和 `revents`（实际发生），**不用每次重置**。
- 但**仍要全量拷贝 + 全量遍历** O(n)。

### 7.3 epoll（Linux 高性能方案）

```c
int epoll_create(int size);                                        // 创建 epoll 实例
int epoll_ctl(int epfd, int op, int fd, struct epoll_event *event); // 注册/改/删 fd
int epoll_wait(int epfd, struct epoll_event *events, int maxevents, int timeout); // 等事件
```

`op`：`EPOLL_CTL_ADD`/`EPOLL_CTL_MOD`/`EPOLL_CTL_DEL`。

**为什么快**：
- 内核用**红黑树**管理所有 fd（增删改 O(logN)）。
- 用**就绪链表**：fd 就绪时内核**回调**把它放进就绪链表。`epoll_wait` 只返回就绪的，O(1)。
- fd 只在 `epoll_ctl` 时拷贝一次，之后 `wait` 不用重复拷贝。
- 无 fd 上限，十万级并发轻松。

### 7.4 LT vs ET 触发模式（epoll 独有）

| 模式 | 触发规则 | 性能 | 编程要求 |
|------|---------|------|---------|
| **LT 水平触发**（默认） | 缓冲区还有数据就**一直通知** | 一般 | 简单，阻塞/非阻塞都行 |
| **ET 边缘触发** | 状态**变化时只通知一次** | 极高 | **必须非阻塞 + 循环读到 EAGAIN** |

> ET 模式坑：必须循环 `read` 直到返回 `EAGAIN`（没数据了），否则数据读不完下次不通知了，数据就丢了。所以 ET **必须搭配非阻塞 IO**。

### 7.5 完整 epoll 示例（LT 模式）

```c
#include <stdio.h>
#include <sys/epoll.h>
#include <sys/socket.h>
#include <unistd.h>
#include <fcntl.h>

int main() {
    int epfd = epoll_create1(0);
    struct epoll_event ev, events[1024];
    ev.events = EPOLLIN;          // 监听可读
    ev.data.fd = 0;               // 监听标准输入
    epoll_ctl(epfd, EPOLL_CTL_ADD, 0, &ev);

    printf("开始监听，输入点东西...\n");
    while (1) {
        int n = epoll_wait(epfd, events, 1024, -1);  // -1 阻塞等
        for (int i = 0; i < n; i++) {
            if (events[i].data.fd == 0) {
                char buf[64];
                int r = read(0, buf, sizeof(buf));
                if (r > 0) printf("收到: %.*s", r, buf);
            }
        }
    }
    close(epfd);
    return 0;
}
```

### 7.6 三者对比

| 维度 | select | poll | epoll |
|------|--------|------|-------|
| 数据结构 | 位图 | 结构体数组 | 红黑树+就绪链表 |
| fd 上限 | 1024 | 无 | 无 |
| 拷贝 | 每次全量 | 每次全量 | 仅注册一次 |
| 检测 | 遍历 O(n) | 遍历 O(n) | 回调 O(1) |
| 触发模式 | LT | LT | LT/ET |
| 跨平台 | 是 | 是 | Linux 独有 |
| 典型应用 | 老旧小并发 | 跨平台中小 | Nginx/Redis 高并发 |

> 企业选型：Linux 高并发必用 epoll。Nginx 用 ET，Redis 用 LT。

## 八、网络编程

### 8.1 网络基础【笔记 0625】

**网络**：通过介质连接计算机设备进行数据通信或设备控制。
- **介质**：有线（网线、光纤、双绞线、同轴电缆）；无线（蓝牙、wifi、zigbee、移动网络、卫星）。
- **设备**：计算机、手机、交换机（组局域网）、路由器（连互联网）、集线器 hub。
- **拓扑**：星形、环形、树形、总线。

### 8.2 OSI 与 TCP/IP 协议栈【笔记 0625】

**OSI 七层模型**（ISO 1984）：应用层、表示层、会话层、传输层、网络层、链路层、物理层。

**TCP/IP 协议族**（美军定义，Vint Cerf / Bill Joy）——实际用的：

| 层 | 协议 | 干什么 |
|----|------|--------|
| 应用层 | HTTP、DNS、SSH、FTP | 应用逻辑 |
| 传输层 | TCP、UDP | 端到端数据传输 |
| 网络层 | IP、ICMP、ARP | 主机到主机寻址 |
| 物理层 | 硬件电气规范 | 比特传输 |

### 8.3 TCP vs UDP【笔记 0706】

| 特征 | TCP | UDP |
|------|-----|-----|
| 建立连接 | 是（三次握手） | 否 |
| 可靠 | 是 | 否 |
| 有序 | 是 | 否 |
| 丢包 | 重发 | 忽略 |
| 数据大小 | 不受限 | 65535，MTU=1500-28 |
| 速度 | 慢 | 快 |
| 应用 | FTP、HTTP（要可靠） | 视频、游戏、传感器（要快） |

### 8.4 C/S 与 B/S 架构【笔记 0703】

- **C/S**：client（客户端，发请求收响应，规模小）/ server（服务器，收请求发响应，规模大复杂）。
- **B/S**：browser（通用客户端）/ server。本质还是 C/S，只是客户端是浏览器。

### 8.5 IP / MAC / 端口【笔记 0703】

- **IP**：接入网络计算机的**逻辑**标识，动态分配。
- **MAC**：6 字节**物理**标识，硬件出厂唯一。
- IPv4：2^32 = 42 亿；IPv6：2^128。
- **端口号**：标识收/发数据的**进程**，2^16 = 65536（2 字节），前 1014 保留。

> 类比：IP = 小区地址，端口 = 门牌号。数据包送到小区（IP）后，靠端口（门牌号）找到具体哪家（进程）。

### 8.6 大小端【笔记 0703/0628】

不同 CPU 存多字节数据顺序不同。数值 `0x12345678`：

```
地址:    0   1   2   3
大端:   12  34  56  78   （高位放低地址）
小端:   78  56  34  12   （低位放低地址）
```

- x86 默认**小端**；网络通信用**大端**（网络字节序）。
- `lscpu` 查本机字节序。

转换函数（"主机↔网络"互转）：

| 函数 | 含义 | 转换大小 |
|------|------|---------|
| `htons()` | host to net short | 2 字节 |
| `htonl()` | host to net long | 4 字节 |
| `ntohs()` | net to host short | 2 字节 |
| `ntohl()` | net to host long | 4 字节 |

> 端口要 `htons` 转了再放进 `sin_port`，否则别的机器读出来是错的端口！

### 8.7 套接字（socket）【笔记 0628/0707】

套接字是 TCP/IP 提供的通信端点，封装了网络底层细节，操作方式**像文件**（也用 fd）。一切皆文件！

### 8.8 TCP 套接字流程

**服务器端**：
```
socket() → setsockopt() → bind() → listen() → accept() → read/write → close()
```

**客户端**：
```
socket() → connect() → write/read → close()
```

各步含义：
| 函数 | 作用 | 谁用 |
|------|------|------|
| `socket()` | 创建套接字 fd | 两端 |
| `bind()` | 绑定 IP+端口 | 服务器 |
| `listen()` | 开启监听，建等待队列 | 服务器 |
| `accept()` | 接受连接，返回新 fd | 服务器（阻塞） |
| `connect()` | 发起连接 | 客户端 |
| `read`/`write` 或 `recv`/`send` | 收发数据 | 两端 |
| `close()` | 关闭 | 两端 |

### 8.9 完整 TCP 服务端示例

```c
/* tcp_server.c */
#include <stdio.h>
#include <string.h>
#include <stdlib.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>

int main() {
    int server_fd = socket(AF_INET, SOCK_STREAM, 0);   // TCP

    struct sockaddr_in addr;
    addr.sin_family = AF_INET;
    addr.sin_addr.s_addr = INADDR_ANY;    // 监听所有网卡
    addr.sin_port = htons(8080);         // 端口 8080，必须 htons!

    bind(server_fd, (struct sockaddr*)&addr, sizeof(addr));
    listen(server_fd, 10);                // 等待队列长度 10
    printf("服务器启动，监听 8080...\n");

    int client_fd = accept(server_fd, NULL, NULL);  // 阻塞等连接
    printf("有客户端连进来了\n");

    char buf[1024] = {0};
    int n = read(client_fd, buf, sizeof(buf));
    printf("收到: %s\n", buf);

    const char *resp = "HTTP/1.1 200 OK\r\n\r\nHello!";
    write(client_fd, resp, strlen(resp));

    close(client_fd);
    close(server_fd);
    return 0;
}
```

编译运行：
```bash
gcc tcp_server.c -o tcp_server
./tcp_server
# 另一终端：nc localhost 8080  或  curl localhost:8080
```

### 8.10 完整 TCP 客户端示例

```c
/* tcp_client.c */
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>

int main() {
    int fd = socket(AF_INET, SOCK_STREAM, 0);

    struct sockaddr_in addr;
    addr.sin_family = AF_INET;
    addr.sin_port = htons(8080);
    inet_pton(AF_INET, "127.0.0.1", &addr.sin_addr);  // IP 字符串转网络地址

    connect(fd, (struct sockaddr*)&addr, sizeof(addr));
    printf("已连接服务器\n");

    write(fd, "Hello Server!", 13);
    char buf[1024] = {0};
    int n = read(fd, buf, sizeof(buf));
    printf("服务器回: %s\n", buf);

    close(fd);
    return 0;
}
```

### 8.11 UDP 套接字流程【笔记 0706】

UDP 无连接，不用 listen/accept/connect。

**发送端**：`socket` → `sendto(data, addr, ...)` → `close`
**接收端**：`socket` → `bind` → `recvfrom` → `close`

```c
// 接收端
int fd = socket(AF_INET, SOCK_DGRAM, 0);    // UDP
bind(fd, ...);
char buf[1024];
struct sockaddr_in src;
socklen_t len = sizeof(src);
int n = recvfrom(fd, buf, sizeof(buf), 0, (struct sockaddr*)&src, &len);
// src 里是发送方地址，可以回信
```

```bash

nohup ./recv &    # 与终端分离（关掉终端程序还在）
```

## 九、进阶主题

### 9.1 Base64 编解码【笔记 0605】

#### 9.1.1 概念
- **摘要/哈希算法**（MD5、SHA128、SHA256）：任意长度输入 → 固定长度输出；**单向不可逆**；用于签名、校验完整性。
- **Base64**：把二进制（文本）编码为**可打印文本**，体积变为原来的 **4/3**；**可逆**可解码。

构成：52 字母（A-Z, a-z）+ 10 数字 + `+` `/`（`=` 用来末尾填充）= 64 字符。用途：电子邮件、网页内嵌图片（`data:image/png;base64,...`）。

> 不是加密！只是编码，谁都能解。别拿它当密码保护。

#### 9.1.2 OpenSSL 库

```bash
sudo apt install libssl-dev libssl-doc
```

BIO 流操作（链式过滤器）：
- `BIO_new(BIO_f_base64())`：创建 Base64 过滤器。
- `BIO_new(BIO_s_mem())`：创建内存 BIO（数据存内存）。
- `BIO_push(base64, bio)`：串联 BIO，形成处理流。
- `BIO_set_flags(base64, BIO_FLAGS_BASE64_NO_NL)`：编码结果不自动换行。
- `BIO_write`：写数据进流（自动编码）。
- `BIO_read`：从流读（自动解码）。
- `BIO_get_mem_ptr`：取出内存 BIO 里的数据。
- `BIO_free_all`：释放整条 BIO 链。

支持字符串级与文件级编解码（`BIO_new_file`）。

#### 9.1.3 加密方式
- **RSA** 非对称加密（公钥加密、私钥解密）。
- 当前常用密码存储策略：**SHA256 + 盐**（salt）。

### 9.2 守护进程【笔记 0706】

类似 Windows 系统服务，**后台自动运行**、与终端分离。`nohup ./prog &` 就是简陋的守护化。

标准守护进程创建步骤：`fork` → 父退出（子成孤儿）→ `setsid`（脱离控制终端）→ `chdir("/")` → `umask(0)` → 再 `fork`（防重新获取终端）→ 关闭标准 fd → 执行业务。

## 十一、新手常见坑汇总

| 坑 | 后果 | 正确做法 |
|----|------|---------|
| `read` 用 `int` 接返回值 | 大文件可能出错 | 用 `ssize_t` |
| 缓冲区不初始化 `={0}` | `write` 写出脏数据 | 初始化或 `memset` |
| `sizeof(buf)-1` 不留位 | `%s` 打印越界 | 给 `\0` 留位置 |
| `open` 用了 `O_CREAT` 不写 `mode` | 权限随机 | 一定写 `0644` 等 |
| 打开文件不 `close` | fd 泄漏，耗尽后 open 失败 | 用完就关 |
| `fork` 后不 `wait` | 僵尸进程占 PID | `wait` 或捕获 `SIGCHLD` |
| 信号处理函数里用 `printf` | 可能死锁 | 用 `write` |
| `pthread_cond_wait` 用 `if` | 虚假唤醒出错 | 用 `while` |
| 端口不 `htons` | 别的机器连错端口 | 一定 `htons` |
| 共享内存不加锁 | 数据竞争 | 配信号量/互斥锁 |
| 编译不写 `-lpthread` | 链接失败 | `gcc xxx.c -lpthread` |
| epoll ET 不循环读 | 数据丢失 | 循环 read 到 EAGAIN |
