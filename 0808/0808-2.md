# 传感器监控

## 传感器数据存储整套方案
 
方案1：直写MySQL（中小QPS，几千条/s）
 
采集线程读传感器数据，放入环形内存缓冲区，条数+时间双阈值；DB线程取出一批，MYSQL_STMT预处理批量写入。
 
- 关闭自动提交，一批一次commit；
- 队列满、数据库写入失败写本地日志兜底；
- 表：主键自增有序，减少索引，可按时间分区；
-  innodb_flush_log_at_trx_commit=2 提升性能，最多丢1秒数据，适合非核心传感器日志。
缺点：峰值压力大时数据库扛不住；程序崩溃丢失内存中未落地数据。
 
方案2：引入消息队列削峰（高并发）
 
采集程序输出到MQ，消费程序批量写MySQL。
 
1. Kafka：磁盘存储，支持大量消息堆积，高吞吐、多副本可靠性高；适合流量波动大、不允许丢数据场景。
2. Redis‑Stream 可以替代Kafka，但有限制
适用：QPS几千以内，已有Redis，不想维护Kafka。
不适用：高QPS、消息大量堆积场景；Redis‑Stream基于内存，堆积会内存暴涨OOM；要设置 MAXLEN 限制消息长度。

 
方案3：海量时序数据
 
使用TDengine / InfluxDB时序数据库，专为传感器时序场景优化，高压缩，写入性能强。

 
## 一、Linux系统监控（CPU、内存）
 
1. CPU使用率
读取  /proc/stat ，获取jiffies时间片；必须两次采样求增量，单次读取无法计算使用率。
总时间 = user+nice+system+idle+iowait+irq+softirq
工作时间 = 总时间 − idle
CPU使用率 =  (工作时间增量 / 总时间增量) ×100% 
 
cpu行是所有核总和；cpu0、cpu1代表各个逻辑CPU。
 
2. 系统内存使用率
读取  /proc/meminfo 。
 MemTotal 总内存；优先用 MemAvailable （真正应用可用内存）。
内存使用率 =  (MemTotal‑MemAvailable)/MemTotal ×100% 
 
MemFree只是完全空闲内存，cache/buffer可以回收，不能当作可用内存。
 
3. 单个进程资源
 
- 进程CPU： /proc/<pid>/stat ，utime(用户态)、stime(内核态)；两次采样结合系统jiffies计算。
- 进程物理内存RSS： /proc/<pid>/statm ，resident字段 ×  sysconf(_SC_PAGESIZE) 。
 
4. 注意： /proc 是虚拟文件，无磁盘IO。CPU采样间隔建议200‑1000ms，间隔太小会除零错误。
 
## 二、多线程 + 环形缓冲区（传感器采集常用）
 
1. 典型模型：采集线程写环形队列，DB写线程读队列。
2. 环形队列要点：
 
-  pthread_mutex_t 互斥锁保护读写； pthread_cond_t 条件变量。
- 队列设置最大长度，防止流量暴涨OOM；队列满数据写本地文件兜底。
- 双阈值触发批量入库：达到条数阈值 或者 达到时间阈值，就写库，避免小流量数据一直滞留内存。
 
3. 线程退出：设置全局运行标志位，信号处理SIGINT/SIGTERM，退出前刷完剩余数据。
4. 坑：忘记加锁、条件变量虚假唤醒；程序崩溃，内存队列未落地的数据丢失。
 
## 、MySQL C‑API 核心考点
 
1. 基础流程： mysql_init → mysql_real_connect → mysql_real_query → mysql_store_result → mysql_free_result → mysql_close 
2. MYSQL_RES：结果集； mysql_store_result 把全部结果读到客户端； mysql_use_result 逐行从服务器读取。
3. 获取列元信息：
 mysql_num_fields() 得到列数；
 mysql_fetch_fields() 获取 MYSQL_FIELD 数组，得到字段名、类型、flags(主键、NOT NULL、自增)；
 
MYSQL_FIELD内存归属MYSQL_RES， mysql_free_result 之后指针失效。
 
4. MYSQL_STMT预处理（重点）
 mysql_stmt_prepare → mysql_stmt_bind_param → mysql_stmt_execute 
 
- 二进制协议，避免SQL注入，适合传感器批量插入。
- 批量写入： mysql_autocommit(conn,0) 关闭自动提交；循环execute一批数据，再 mysql_commit() ；之后恢复自动提交。
 
5. 断线重连： mysql_ping() 检测连接断开，执行重连逻辑。
6. 批量写入注意：控制批次500‑2000条，不要超大事务，防止undo膨胀、主从延迟。
 
## 四、MySQL索引 & SQL优化
 
1. InnoDB聚簇索引
 
- 主键（聚簇索引）：B+树叶子保存完整一行数据。
- 二级索引：叶子存索引列+主键；查到主键后，去聚簇索引读取完整行，这个过程叫回表，带来额外IO。
- 覆盖索引Using index：查询字段全部存在二级索引中，不需要回表。 explain  Extra出现 Using index 。
 
2. 索引失效场景
 
- 索引列做函数、算术运算；
- 隐式类型转换；
-  like '%xxx' 通配符在开头；
- or条件一侧无索引；
- 联合索引不满足最左前缀。
 
3. explain关键字段
 type ：性能从优到劣  system>const>eq_ref>ref>range>index>ALL ，ALL代表全表扫描。
 key ：实际使用索引； rows 预估扫描行数。
 Extra ： Using index 覆盖索引； Using filesort 文件排序； Using temporary 临时表，需要优化。
4. SQL优化要点
 
- 禁止 select * ；尽量覆盖索引，减少回表。
- limit深度分页：延迟关联优化。
- 优先 union all ，少用union（union会排序去重开销大）。
- 慎用 not in ，存在NULL陷阱，改用 not exists 。
- join小表驱动大表，on字段建索引。
